D — TWO VOICES prose gets a reading face; structure stays mono

A system prompt is mostly prose, but the editor typesets every word as source code — one mono texture at code density. This variant keeps the exact lines, order, indentation and gutter, and splits the text into two voices: sentences render in a serif reading face at 15px/1.55 on a ~68ch measure, while tags, inline code, variables and grammar tokens stay mono at .88em — so code-ness becomes a deliberate contrast inside the prose, like inline code in good technical writing.

  • “A label … and an article paragraph should not share one set of rules” — the whole premise: prose and structure get separate rules. better-typography/SKILL.md
  • “Pair for contrast, not similarity” — serif against mono reads as a deliberate display/reading split; two families total, page-wide. choosing-fonts.md
  • Serif for “long passages, editorial reading” — this document is long instructional prose, so it gets the serif; ui-serif/Georgia, screen-proven, no webfonts. choosing-fonts.md
  • “Cap the measure” at 60–75ch and “line-height by role” (body 1.5–1.6, unitless) — prose caps at ~68ch/1.55; the old 136ch mono wall is gone. better-typography/SKILL.md §7, §9
  • “One color, one meaning” — teal is kept for exactly one thing: inline code and variables. Tags drop from purple to a three-step gray ramp; nothing else carries hue. better-colors/color-usage.md
  • “Tabular numbers” via font-variant-numeric (property over raw tag) on every mono token and the gutter. better-typography/SKILL.md §2, §11
