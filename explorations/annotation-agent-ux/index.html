Prompt annotation → agent edit loop

Interactive mockup of the design session in docs/.drafts/2026-07-31-annotation-agent-ux-session.md. Everything is simulated client-side; the point is to feel the loop, not to be real.

ANNOTATE

Hover blocks for the targeting ring; click and the composer opens inline, directly above what you clicked (⌘⏎ submits, Esc cancels). What you click is the target — no scope picker. Drag across text for a range target — the real lab requires ⌘-drag; here plain drag works. The top rail input messages the whole document (same queue, document target).

THE RUN

"Apply N notes" starts one agent session over every open request (R1, R2…). The scripted demo: the agent asks a clarifying question on R2 (reply to unblock it — it keeps working the others), then stages its edits. Nothing touches the "live" prompt until you accept.

INLINE REVIEW

Staged changes land in the file itself: red/green diff lines in place, each with a small action bar (R-alias + note + Accept/Reject). Accept/reject is per request, not per hunk. Accept advances the revision hash and the text becomes real; Undo lives on the request card in the rail. You can keep annotating while a draft is staged.

THE DOCK

Secondary dock: the session's design decisions and open questions as live artifacts — click a pill to cycle its status (persisted locally). The DEMOS tab stages the three open UX questions (inline agent threads, inline structural moves, queue-overview rail) so you can compare them in place. The log tab records every loop event, timestamped.
